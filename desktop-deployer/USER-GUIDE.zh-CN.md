# GLaDOS Quick Deploy 中文使用指南

**适用版本：1.0.0**

安装并打开应用，选择登录浏览器后点击“一键部署”。需要时，你只负责在 GitHub 官方页面完成授权、在 GLaDOS 官方页面完成登录；仓库创建、登录信息配置、计划任务与首次运行验证由软件自动接续。

## 1. 选择并安装对应版本

| 你的电脑 | 使用的安装包 |
| --- | --- |
| Windows，Intel / AMD 64 位电脑 | Windows x64 的 `.exe` 安装包。 |
| 配备 Apple Silicon、运行 macOS 13 或更新系统的 Mac | macOS ARM64 的 `.dmg` 或 `.zip`。 |
| 配备 Intel 处理器、运行 macOS 13 或更新系统的 Mac | macOS x64 的 `.dmg` 或 `.zip`。 |

Mac 最低要求为 **macOS 13 Ventura**；macOS 12 或更早系统不在本版本支持范围内。

Windows 打开安装程序，按向导选择安装目录。Mac 打开 DMG 后把应用放入自己的应用目录；使用 ZIP 时，解压后移动 `.app` 再打开。使用 MacData 的 Mac 可以将应用放在 `/Volumes/MacData/Applications` 下，保持外置安装习惯。

安装包已包含应用所需组件，不需要另外安装开发工具或 GitHub CLI。

**签名说明：** Windows 版本尚未使用微软代码签名证书；Mac 版本使用 ad-hoc 签名，未完成 Apple 开发者公证。系统可能显示来源确认提示。先确认包来自本次交付或可信源码构建，并核对随包校验值，再按系统提供的正常提示处理。如系统不允许正常打开，应先核查原因，不要关闭系统安全保护。

## 2. 保持默认设置即可开始

| 设置 | 默认值与作用 |
| --- | --- |
| 登录浏览器 | 优先使用识别到的 Brave；也可以选择“应用内登录窗口”。 |
| GitHub 仓库名称 | `glados-quick-deploy`。软件自动创建或更新自己的专用部署仓库。 |
| 每日运行时间 | **09:30，UTC+8**，即北京时间 / 台北时间。GitHub 排队可能使实际运行延后。 |
| 积分兑换 | **500 积分换 100 天**。也可改为 200 积分换 30 天、100 积分换 10 天，或关闭自动兑换。 |

达到所选计划的条件后，任务会尝试兑换，是否成功以服务端结果为准。

仓库名称为 1–80 个字符，以英文字母或数字开头，可包含点、横线和下划线。同一仓库的全部账号共用设置中的运行时间和兑换计划；再次部署时修改这些设置，会对该仓库生效。

## 3. 点击“一键部署”并完成登录

**GitHub 授权。** 如果电脑上的官方 GitHub CLI 已有可用身份，软件会复用它。需要登录或补充权限时，应用显示设备授权码，并打开 GitHub 官方授权页面。按照网页提示登录、输入显示的授权码并确认页面列出的授权。完成后应用自动继续，不需要手动创建令牌。界面右上角显示实际使用的 GitHub 账号；需要重新授权时使用该按钮。

**GLaDOS 登录。** 软件打开专用登录窗口，在里面使用你希望部署的 GLaDOS 账号登录。邮箱验证码以及官网要求的其他验证都由你在官网完成。不要把密码、验证码或 Cookie 发给他人，也不需要把它们复制进应用设置。

**自动部署与验证。** 登录身份确认后，程序自动配置仓库和该账号的登录信息，启动首次验证并显示进度。如果同一仓库已有任务在运行，程序会等待后接续，避免同时提交多组账号操作。

点击“取消任务”可以停止当前本机操作。已经提交到 GitHub 的运行可能继续，取消本机等待不会自动撤回它。

## 4. 看懂结果再判断是否成功

| 界面结果 | 应如何理解 |
| --- | --- |
| 已加分 +N | 本次有可核实的积分增加。 |
| 今日已签到 | 服务端结果表明该账号今天已经签过到。 |
| 签到成功 | 有对应账号的签到接受结果，但不一定核实了新增积分。 |
| 工作流成功 | GitHub 工作流运行成功；仅凭这项不能判断一定加分，应查看账号提示和运行记录。 |
| 验证排队 / 正在验证 | 尚未取得最终结果。等待自动更新或使用账号卡片的刷新按钮。 |
| 运行异常，同时显示已加分 | 已经取得积分，但兑换或其他运行步骤有问题，仍需查看具体记录。 |
| 需要重新登录 / 授权被拒绝 | 当前会话没有被网站接受，按下节重新登录更新。 |

“部署进度完成”与“网站确实加分”是不同结果，应同时查看账号卡片。软件的构建检查与窗口检查也不能证明你的账号已签到。

**本版本尚未通过真实账号的完整端到端登录、部署、签到及兑换验收。** 首次使用时，账号卡片和 GitHub 上本次运行的实际结果才是验收依据。GLaDOS 后续可能调整认证或自动化检测，本软件不保证所有账号和未来版本长期免维护。

## 5. 添加账号、更新会话与暂停

**添加账号：** 点击“一键部署”或“部署另一个账号”，在专用窗口登录另一个 GLaDOS 账号。使用同一仓库名称即可加入同一套任务；不同账号的登录信息分别保存。

**更新原账号的登录信息：** 使用同一 GitHub 账号和原仓库名称重新部署，在 GLaDOS 窗口登录需要更新的原账号。程序根据核验到的账号标识更新对应记录，无需手动编辑 Secrets。网站明确要求重新登录时，重复刷新旧会话不会代替新的官方登录。

**查看运行：** 账号卡片可以刷新结果、打开 GitHub 运行记录或打开所属仓库。如果登录提示或结果异常，先看这一账号的具体说明，避免把一般网络错误和登录拒绝混为一谈。

**暂停 / 恢复：** 暂停操作作用于**此仓库全部账号**，不是只暂停当前这一张账号卡片。恢复也对同一仓库一起生效。需要分别设定时间、兑换计划或独立暂停的账号，应使用不同仓库。

部署完成后可以退出应用、关闭电脑，已建立的 GitHub Actions 仍按计划运行。想停止云端定时签到，请先暂停对应仓库；仅退出应用或卸载应用不会删除 GitHub 上的任务。

## 6. 浏览器如何选择

应用会检查 Brave、Chrome、Edge、Firefox、Opera、Vivaldi、Chromium，以及 macOS 上的 Arc 的常见安装位置。不同浏览器版本、安装位置和连接协议会影响可用性；本版本没有对所有品牌、版本和电脑逐一完成真实登录测试。

优先使用应用已识别到的 Brave 或其他 Chromium 系浏览器。外部浏览器连接失败、安装位置未被识别，或不想使用外部浏览器时，可以选择**应用内登录窗口**，无需安装浏览器扩展。

Safari 可作为 GitHub 网页授权使用的浏览器，但本版本不通过 Safari 自动取得 GLaDOS 登录会话。Mac 上的 GLaDOS 登录请选其他已识别浏览器，或应用内窗口。

软件为 GLaDOS 打开独立的专用登录会话，不使用日常浏览器的个人 profile。完成登录或取消后会关闭本次专用窗口，这不会清空你日常浏览器的账号。

## 7. 数据放在哪里，哪些内容会公开

软件会在你的 GitHub 中自动建立专用的**公开部署仓库**。公开部分包含任务配置、上游版本与不含邮箱的账号 ID，不包含账号 Cookie。每个账号的会话分别保存在 GitHub Actions Secrets 中，不需要你手动粘贴。

本机保存应用设置、账号邮箱、仓库与运行结果，方便下次打开后查看。GLaDOS Cookie 不写入本地部署状态文件；外部浏览器登录期间使用应用管理的临时目录，正常结束时清理。如果目录暂时被系统占用，应用会在后续启动时重试清理。内置登录窗口使用独立的非持久化会话。

GitHub 身份由官方 `gh` 的标准会话机制管理，软件会复用已有登录，不退出或清空原有会话。官方 `gh` 的凭据存储与 GLaDOS 临时登录数据不同，不应把本软件理解为“所有授权信息只存在于内存”。

应用底部的“本机数据位置”显示实际数据目录。Mac 检测到可写的 MacData 时，优先使用 `/Volumes/MacData/Applications/GLaDOSQuickDeploy/Data`；其他电脑使用系统应用数据位置。
