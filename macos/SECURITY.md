# 手动账号资料与安全边界

## 登录与保存

- 仅在用户点击读取、保存、导入或同步时处理登录资料。应用没有自动取验证码、自动登录、定时维护登录或自动更新 Cookie 的入口。
- 每个账号的邮箱和设置保存在本机 `ManualAccounts/accounts.json`，目录权限为 0700，文件为 0600。邮箱不随状态接口失败而清空。
- 完整的手动会话保存在 macOS 钥匙串的 `com.enoch.glados-account-center.manual-sessions`，不启用钥匙串云同步；保存新会话前先完成本机写入。
- 手动会话包括完整适用 Cookie、实际浏览器 User-Agent、原登录域名、稳定账号 ID、邮箱、浏览器与读取时间。支持新版不透明的 `gld:sess` / `gld:sess.sig`，保留同一来源适用的旧 Cookie 和辅助 Cookie。
- Cookie 不显示在界面，不写进账号状态缓存、公开仓库、命令行参数或诊断日志。向 GitHub Secret 写入时只通过标准输入传给 `gh secret set`。
- 旧的 `login-refresh.sqlite` 仅读取邮箱身份；原数据库和原钥匙串项保留。显式导出时可读取旧 `active-KEY` / `candidate-KEY`，作为旧格式归档携带，不补造浏览器上下文。若需原 `RefreshSecretStore` 的访问控制，只使用其只读 `get` 操作。

## 导入与导出

- 用户在同一 App 中选择导入、导出文件。导出使用 PBKDF2-HMAC-SHA256（600,000 次、随机 32 字节盐）派生密钥，AES-256-GCM 加密和校验；格式头参与认证。密码不会保存。
- 导入先解密和验证整个文件，再按稳定账号 ID 去重。已有本地账号、已有云端账号或已有独立 Secret 都会跳过，不用导入的 Cookie 覆盖。
- 本地批量写入失败会回滚本批次新建的钥匙串项；已有资料不被改写。云端同步失败保留本机资料并显示待处理状态。
- GitHub Secret 的写接口没有条件创建语义；应用在写入前再次检查账号及 Secret 名单，并保留配置文件的版本检查，但无法承诺与外部同时写 Secret 的客户端实现跨系统事务。
- 只有邮箱的旧记录也会保留并导出，界面标记待补登录资料。只存在于 GitHub Secret 的旧 Cookie 无法由本应用读回；需要用户手动重新读取才能形成完整本机副本。
- 加密文件能校验备份是否完整，不能让已被服务器撤销的会话重新有效。结构化会话执行写请求前还要核对服务端账号身份。

## 浏览器与请求边界

- 手动捕获固定到用户选择的登录来源。结构化会话请求固定同一个 HTTPS 域名，不在别的域名重放 Cookie，不跟随跳转发送凭据。
- 只使用实际读取到的浏览器 User-Agent，不生成浏览器指纹或 Client Hints。出现设备不匹配、网页验证或明确拒绝时停止，不尝试绕过。
- 不将读取积分成功当作签到成功，不把 `code=-2` 推断为具体过期时间，不把旧 `koa` 字段中的时间当成新版会话有效期。
- Safari 仅在用户主动点击扩展时，通过有一次性令牌和来源限制的本机桥接发送同一页的 Cookie 与实际 User-Agent。扩展是主 App 内的标准 `.appex`，没有第二个 Bridge App。
- CI 使用合成 Cookie 和隔离测试存储，不使用真实账号、真实钥匙串、登录页面、验证码或签到/兑换接口。

## 安装与保留数据

`build-manual.sh` 可以在已经核对过的旧 App 上重建主程序和指定组件，保留其他资源；`install-manual.py` 要求候选包记录的原包摘要与当前安装一致，并保留可验证的回退包。仅停止旧登录维护任务；原签到排程、账号、兑换策略、状态历史、浏览器资料和钥匙串数据继续保留。

macOS 编译、包签名与离线测试不替代实际电脑上的安装、界面和真实登录验收。
